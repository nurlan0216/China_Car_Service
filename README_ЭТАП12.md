# China Car Service — сборка после Этапа 12

Эта сборка содержит все файлы проекта в актуальном состоянии, включая
Этап 12 (проверено — уже реализовано в присланных вами файлах, отдельно
дорабатывать не пришлось):

- 12.1 — самообслуживаемый сброс пароля сотрудника супер-админом
  (`resetAdminPassword_`, `apiAdminResetPassword`, карточка в `to.html`).
- 12.2 — диагностика и переустановка Telegram-вебхука из интерфейса
  (`apiTelegramDiagnostics`, `apiTelegramReinstallWebhook`), плюс
  директору теперь приходит текст ошибки обычным сообщением в чат, если
  нажатие «Разрешить/Запретить» не применилось (`handleTelegramCallback_`).
- 12.3 — список зависших заявок «на согласовании» с ручным решением из
  `to.html` (`apiListPendingApprovals`, `apiDecideApprovalRequest`) и
  автоматическое протухание таких заявок через
  `autoExpireStaleApprovalRequests` (нужно один раз запустить
  `installApprovalAutoExpireTrigger` из редактора Apps Script).

## Перед деплоем — обязательно вручную

1. `apps-script/*.gs` — залить в редактор Apps Script (или `clasp push`),
   сделать **New deployment** веб-приложения.
2. Если раньше уже был настроен Telegram-бот — после нового деплоя
   (меняется URL) переустановить вебхук: кнопка в `to.html` (Этап 12.2)
   или вручную `setupTelegramWebhook()` из редактора.
3. Один раз (если ещё не делали) выполнить из редактора Apps Script:
   - `installApprovalAutoExpireTrigger` — автопротухание заявок (раз в час).
   - `installStoriesCleanupTrigger` — автоочистка Stories (раз в 10 мин),
     если ещё не установлен.
4. Проверить чек-лист из `ЭТАП_12_промт.md` (раздел «Финальная проверка»)
   и пункты 12.1–12.3 руками на реальном окружении.

## Примечание

`CHANGES_RU.md` из исходного архива (Этап 10) сюда не включён — он не
описывает этапы 9–12, и включать частично устаревший файл было бы
вводящим в заблуждение. Актуальное описание Этапов 9–12 — комментарии
"ЭТАП N" прямо в коде (`.gs`) и в `ЭТАП_12_промт.md`.
